# Bank Customer Churn Prediction — Kaggle Playground Series S4E1

A machine-learning project that predicts whether a bank customer is likely to leave the bank (`Exited = 1`) or remain a customer (`Exited = 0`). The notebook builds a complete tabular-classification workflow, from exploratory data analysis and feature engineering to gradient-boosting models, hyperparameter tuning, stacking, and model interpretation.

**Kaggle competition:** [Binary Classification with a Bank Churn Dataset — Playground Series S4E1](https://www.kaggle.com/competitions/playground-series-s4e1)  
**Primary evaluation metric:** ROC-AUC

## Project overview

The project explores and compares multiple approaches rather than assuming that a more complex model will always perform better.

- **Data analysis:** review feature distributions, missing values, target balance, and churn rates across customer groups.
- **Feature engineering:** create customer-level ratios, interactions, age groups, tenure groups, credit-score bands, and categorical product-count features.
- **Baseline models:** evaluate a dummy classifier, logistic regression, and baseline XGBoost.
- **Hyperparameter optimization:** use Optuna to tune XGBoost, LightGBM, and CatBoost.
- **Unsupervised feature experiments:** use PCA and KMeans, then compare their added features against the engineered-feature baseline.
- **Ensembling:** train a logistic-regression meta-model from out-of-fold predictions generated by XGBoost, LightGBM, and CatBoost.
- **Interpretability:** inspect LightGBM feature importance and use SHAP summary plots to understand model predictions.

## Notebook

Main file: **[`Bank_Customers_Churn_Prediction.ipynb`](Bank_Customers_Churn_Prediction.ipynb)**

The notebook is organized into these stages:

1. Load the competition data and inspect the dataset.
2. Perform exploratory data analysis (EDA).
3. Engineer features and prepare the training and validation sets.
4. Establish baseline metrics.
5. Tune XGBoost, LightGBM, and CatBoost with Optuna.
6. Evaluate PCA and KMeans feature experiments.
7. Compare tuned models on a held-out validation split.
8. Build an out-of-fold stacking ensemble.
9. Review feature importance and SHAP explanations.

## Validation results

The table below contains the notebook's held-out validation results. **ROC-AUC is the primary model-selection metric.** Accuracy, precision, recall, and F1 use a probability threshold of `0.50`; log loss evaluates the predicted probabilities.

| Model | ROC-AUC | Accuracy @ 0.50 | Precision @ 0.50 | Recall @ 0.50 | F1 @ 0.50 | Log loss |
|---|---:|---:|---:|---:|---:|---:|
| **XGBoost tuned** | **0.89019** | 0.86518 | 0.74459 | 0.55226 | 0.63417 | **0.31887** |
| OOF stacked ensemble | 0.88989 | 0.86542 | 0.74834 | 0.54840 | 0.63295 | 0.32904 |
| LightGBM tuned | 0.88976 | 0.86512 | 0.74525 | 0.55083 | 0.63346 | 0.31943 |
| XGBoost baseline | 0.88945 | 0.86527 | 0.74371 | 0.55427 | **0.63516** | 0.31952 |
| CatBoost tuned | 0.88881 | 0.86454 | **0.74965** | 0.54023 | 0.62794 | 0.32044 |
| Logistic regression | 0.87701 | 0.86200 | 0.74305 | 0.53164 | 0.61981 | 0.33335 |
| Dummy / prior | 0.50000 | 0.78841 | 0.00000 | 0.00000 | 0.00000 | 0.51606 |

These are local validation metrics, not Kaggle public or private leaderboard scores.

### Key findings

- **Tuned XGBoost achieved the highest validation ROC-AUC (0.89019)**, narrowly ahead of the out-of-fold stacked ensemble (0.88989).
- **Stacking did not beat the strongest individual model on ROC-AUC.** The tuned XGBoost, LightGBM, and baseline XGBoost scores were close, while the dummy classifier's 0.50000 ROC-AUC shows why accuracy alone is not a sufficient comparison.
- **PCA and KMeans did not improve the feature-ablation score:** engineered features scored 0.889575 versus 0.889070 with PCA and KMeans added. PCA used 9 components and captured 98.93% cumulative explained variance; one KMeans cluster contained only 8 training rows.

## PCA and KMeans experiment

PCA was configured to retain at least 95% variance. It selected 9 components, with cumulative explained variance of `0.9893` (98.93%). KMeans was configured for five clusters.

| Feature set | Validation ROC-AUC |
|---|---:|
| **Engineered features only** | **0.889575** |
| Engineered features + PCA + KMeans | 0.889070 |

Adding PCA and KMeans decreased ROC-AUC by `0.000505` in this comparison. The notebook therefore treats these techniques as exploratory analyses instead of assuming they improve the final model.

## Reproducibility notes

- The main validation split uses stratification and a fixed random seed (`42`).
- Preprocessing, PCA, and KMeans are fitted on training data before transforming validation data.
- Optuna tuning uses stratified cross-validation. The current configuration uses 15 trials for XGBoost and LightGBM, and 2 trials for CatBoost.
- `USE_ORIGINAL_DATA = False` by default. When enabled, the optional original dataset is added only to model-fitting partitions, not to the held-out competition validation labels.
